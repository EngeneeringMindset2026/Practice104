# Лабораторная работа №104

## Тема: Docker for Beginners

### Цель работы
- Познакомиться с технологией контейнеризации Docker.
- Изучить базовые команды Linux.
- Научиться создавать, запускать и управлять Docker-контейнерами.
- Освоить создание собственных Docker-образов с помощью Dockerfile.
- Изучить механизм Bind Mount.
- Научиться публиковать Docker-образы в Docker Hub.

## Ход работы

### Task 0. Подготовка окружения
Был клонирован учебный репозиторий [linux_tweet_app](https://github.com/dockersamples/linux_tweet_app).
Подготовлено окружение Docker и создан аккаунт на Docker Hub.

### Task 1. Запуск Docker-контейнеров
В ходе задания были запущены контейнеры Alpine Linux, Ubuntu и MySQL.

**Alpine Linux:**
- Запущен контейнер с выполнением команды `hostname`.
- Получен идентификатор контейнера.
- Проверен статус завершённого контейнера командой `docker container ls --all`.

**Ubuntu:**
- Запущен интерактивный контейнер Ubuntu.
- Изучены команды `ls /`, `ps aux`, `cat /etc/issue`.
- Выполнен выход из контейнера с его автоматическим удалением.

**MySQL:**
- Запущен контейнер базы данных в фоновом режиме.
- Изучены команды `docker container logs`, `docker container top`, `docker exec`.
- Проверена версия MySQL 26.10.0.
- Выполнено подключение к командной оболочке работающего контейнера.

Скрипт задания: `scripts/01-containers.sh`.

### Task 2. Создание собственного Docker-образа
Изучен Dockerfile приложения на базе Nginx.

Использованные инструкции:
- `FROM` — выбор базового образа.
- `COPY` — копирование файлов приложения.
- `EXPOSE` — указание используемых портов.
- `CMD` — определение команды запуска.

Собран Docker-образ `neuralman159/linux_tweet_app:1.0`.
Запущен контейнер с публикацией порта `80:80`. Работа веб-приложения проверена в браузере.
После проверки контейнер был удалён.
Скрипт задания: `scripts/02-build-app.sh`.

### Task 3. Изменение работающего приложения
Изучен механизм Bind Mount, позволяющий подключать файлы с компьютера к контейнеру.

В ходе задания:
1. Запущено веб-приложение с Bind Mount.
2. Файл `index.html` заменён содержимым `index-new.html`.
3. Установлено, что изменения отображаются на сайте без пересборки образа.
4. Проверено, что исходный образ версии `1.0` остался неизменным.
5. Собран новый Docker-образ версии `2.0`.
6. Обе версии сайта запущены одновременно на разных портах:
   - Версия `1.0` — `http://localhost:8080`, голубой фон.
   - Версия `2.0` — `http://localhost:80`, оранжевый фон.
7. Обе версии опубликованы в Docker Hub.

Скрипт задания: `scripts/03-modify-app.sh`.

## Запуск проекта

Для воспроизведения заданий необходимы Linux, Docker Engine и Bash. Порты 80 и 8080 должны быть свободны.
Из каталога проекта предоставить скриптам права на выполнение:
`chmod +x scripts/*.sh`

Последовательно выполнить:
1. `./scripts/01-containers.sh`
2. `./scripts/02-build-app.sh`
3. `./scripts/03-modify-app.sh`

При выполнении интерактивных заданий необходимо вводить команды внутри контейнеров согласно комментариям в скриптах.
Для публикации образов в Docker Hub необходима авторизация.
