# Практическая работа № 104. Docker

## Цель работы

Освоить базовые команды Linux и Docker. Научиться запускать контейнеры, собирать образы из Dockerfile и публиковать их в Docker Hub.

## Ход работы

1. В Ubuntu внутри VMware запустил одноразовый контейнер Alpine и выполнил в нём `hostname`. После выполнения команды контейнер завершился с кодом `0`.
2. Запустил интерактивный контейнер Ubuntu и проверил его файловую систему, процессы и версию ОС. Затем запустил MySQL в фоне и проверил его журнал, процессы и версию клиента.
3. Собрал образ сайта на NGINX с тегом `1.0`. Запустил контейнер и получил ответ `200 OK` на порту `8080`.
4. Подключил каталог сайта через bind mount и заменил `index.html`. Контрольная сумма страницы изменилась без пересборки. После повторного запуска образа `1.0` без монтирования сервер снова отдал исходную страницу.
5. Собрал образ `2.0` с изменённой страницей. Запустил обе версии одновременно на портах `8080` и `8081`, сверил контрольные суммы страниц и опубликовал оба тега.

[Образы 1.0 и 2.0 в Docker Hub](https://hub.docker.com/r/imegor/linux_tweet_app/tags)

## Как воспроизвести

Понадобятся Docker Engine с Buildx, `curl` и свободные порты `18080` и `18081`. Выполни команды из каталога с `lab.sh`.

```bash
sudo ./lab.sh containers
sudo ./lab.sh website
```

## Выводы

Контейнер работает, пока запущен его основной процесс. Это видно на примере Alpine, который завершился после выполнения `hostname`, и MySQL, который продолжил работать в фоне.

Образ содержит файлы, добавленные при сборке. Bind mount позволяет работающему контейнеру читать файлы из Ubuntu, поэтому изменение страницы сразу отразилось на сайте. Повторный запуск образа `1.0` без монтирования вернул исходную страницу. Чтобы сохранить изменение для других пользователей, я собрал образ `2.0` и опубликовал его в Docker Hub.
